PRODUCTION ENGINEERING
04 / 10
Decisions, not technologies
Every choice exists for a reason — here is why.
Durable ingestion
An uploaded document must not silently vanish if the process dies.
Postgres-backed job queue
A queue you can inspect, migrate, and trust — not a black box.
Redis for caching only
Speed where it helps; never a second source of truth.
Streaming responses (SSE)
Honest token-by-token output; perceived latency drops.
Audit logs
Know who did what, when — a fail-closed contract.
Health checks · liveness vs readiness
“Am I alive” and “can I serve traffic” are different questions.
Correlation IDs
One request, one traceable thread through every log line.
Retry strategy
Classify errors; only retry the retryable — never the fatal.
Rate limiting
Protect a shared, finite model quota from one noisy tenant.
CI/CD
Every merge is a linted, migrated, tested, deployable artifact.

ENGINEERING TRADE-OFFS
05 / 10
Engineering is about trade-offs
Five decisions, each with a considered alternative.
01
Problem

In-process background work can be killed mid-flight (idle sleep, OOM).

Chosen

Postgres job table — SKIP LOCKED claim, stale-lease reaper, backoff.

Alternative

Redis/Arq queue or a separate worker fleet.

Trade-off

Inspectable + durable for throughput; single-process coupling.

02
Problem

Fast shared state without inventing a second datastore.

Chosen

Redis for cache + rate-limit only.

Alternative

Redis as a source of truth / job store.

Trade-off

Speed without dual-write complexity; Redis never holds ground truth.

03
Problem

Long ingestion must not block requests; free tier has no worker service.

Chosen

In-process asyncio worker over the durable job table.

Alternative

Separate worker containers.

Trade-off

Zero extra infra for crash-coupling; evolves into a real fleet.

04
Problem

Files must be durable and URL-safe, not local to a stateless container.

Chosen

S3-compatible object storage — opaque keys, no server filesystem.

Alternative

Local disk / SQLite sidecar.

Trade-off

Network dependency for durable, portable, shared blobs.

05
Problem

Answers take seconds; the user should see them arrive.

Chosen

SSE with a final structured citation event.

Alternative

WebSockets or plain polling.

Trade-off

Simple one-way HTTP streaming for no bidirectional channel.

Every decision names what it gave upCampusBrain

Recovery

Recovery

Upsert-then-prune idempotency

PRODUCTION CONCEPTS
07 / 10
Concepts over technologies
The ideas behind the system — each with a job to do.
Distributed Systems
Many parts act as one; failure is the default assumption.
Caching
Skip expensive work when the answer is already known.
Retry Logic
Not all errors are equal — retry the retryable only.
Observability
You cannot fix what you cannot see.
Audit Logging
Every consequential action leaves a durable record.
Structured Logging
Machine-readable logs a correlation ID can tie together.
RBAC
Access is a role decision, not a feature flag.
Multi-tenancy
One platform, isolated per org at the data layer.
Hybrid Retrieval
Semantic recall plus exact-keyword precision, fused.
Reranking
Measured, added no value on our data — deliberately rejected.
Streaming
Deliver the result as it is produced.
Evaluation
Quality is a number you can move, or it is an opinion.
Cost Tracking
Model spend is a ledger with an owner, not a surprise invoice.
Background Workers
Long work leaves the request path.
Health Checks
Liveness and readiness are different contracts.

SCALING JOURNEY
08 / 10
The scaling journey
What breaks, what changes, what evolves — at each order of magnitude.
10 users
What breaks
Nothing — a single worker and free tier are enough.
100 users
What breaks
Concurrent chats. Per-org collections + RBAC start paying off.
1K users
What breaks
Hand-rolled IDF filter becomes the latency floor → real BM25.
10K users
What breaks
Per-chunk HTTP embedding (248 s) → batch + scale workers.
100K users
What breaks
Per-org collections strain Qdrant → shared + tenant filter.
1M users
What breaks
Everything becomes a distributed-systems problem.
The architecture changes at every stage. The invariants — tenancy, durability, audit — do not.CampusBrain
LESSONS LEARNED
09 / 10
Lessons from building — and operating
What the demo never teaches you.
Building AI is easy. Operating AI systems is hard.
Reliability matters more than features.
Good architecture is about trade-offs, not choices.
Simple systems outperform unnecessary complexity.
Measure before you build — we rejected the reranker with data.
